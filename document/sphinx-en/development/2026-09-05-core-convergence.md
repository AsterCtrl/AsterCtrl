# Core convergence: implementation journal

Status: in progress. This is not a release announcement.

## Implemented and checked

- Reproduced and fixed dynamic Package instances losing their assigned CoreRef.
- Made public service references single-pointer C ABI facades. Backend dispatch
  and fixed-capacity local implementations now live in the Runtime SDK.
- Moved Runtime, platform and Transport headers out of the Module Interface tree;
  introduced the separate `aster::runtime_interface` CMake target.
- Added Host exception translation for Module initialization and startup, keeping
  shutdown non-throwing and the embedded build exception-free.
- Introduced ABI 2 tagged configuration/parameter values instead of interpreting
  arbitrary C++ object memory as configuration. Parameter payload reads copy into
  caller-owned storage; immutable configuration payloads remain borrowed.
- Split build options, Interface targets, installation and tests into `cmake/`.
- Corrected the release workflow's bilingual documentation job name.
- Added independent instance identity and Runtime-supplied execution context.
- Made Clock failures explicit and migrated CAN clock readers.
- Connected `aster run --config` to the generic launcher without a Deployment Lock.
- Wired v1alpha3 Host parsing, named serial/thread-pool executors, typed instance
  configuration/parameters and instance-aware logging.
- Added namespace/remap-aware Local Channel with owned asynchronous payloads.
- Separated RPC instance/method identity, reserved completion capacity, deadlines
  and shutdown cancellation.
- Generated Packages link Module/Package Interfaces, not Runtime.
- Pinned yaml-cpp by archive digest, supported pre-fetched source and installed its license.
- Replaced the default init template with a v1alpha3 Linux project; Package entries
  are generated by `aster_add_package` from export-only metadata.
- Removed the old package dependency manager and its release-workflow invocations.
- Verified a separately installed SDK builds the template and YAML-only changes
  leave its Package binary unchanged. Duplicate YAML keys now fail validation.

Key regressions failed before their fixes. The local macOS Host passed 36 C++ tests
with AppleClang and LLVM 18, 129 Python tests, ASan/UBSan, TSan, installed independent
consumers, forbidden dependency/pin checks, spelling and bilingual Doxygen/Sphinx
builds. The bounded protobuf decoder completed 10,000 libFuzzer runs with sanitizers.
Pre-fetched yaml-cpp configured and built with network access denied by the macOS
sandbox; a connection probe verified the restriction. Linux CI has an equivalent
network-namespace build step, not yet executed remotely. Targeted clang-tidy 18
checks passed for the new Host managers, parser, Runtime and execution scope.

Package generation uses isolated Python imports. A regression test plants a
shadowing application-owned Python file and verifies that it is not executed.

The integration test combines two instances of one dynamic type with a static
receiver. YAML-only parameter changes alter results. Shutdown releases Package
handles; initialization/start failures discard queued callbacks before unloading.

## Remaining acceptance work

- CorePlugin lifecycle and backend registration in the production startup path.
- Optional v1alpha3 Deployment compilation and static Zephyr emitters.
- CAN/USB wiring into the new launcher, contract identity and registration checks.
- Removal of generic Hardware/Capability/Provider orchestration.
- v1alpha3 cross-platform examples and website migration; bilingual default
  tutorials are now aligned, but old examples do not qualify the new deployment path.
- Linux GCC, network-isolated CI and board compilation verification.
- Physical board smoke and cross-node hardware tests; none are claimed complete.

## Follow-up: documentation consistency and omitted checks

Current guides no longer require two user-authored graphs. Retained
Graph/Provider/Transport code is explicitly labeled as migration regression
coverage. The [implementation audit](convergence-audit.md) reconciles each plan
item without rewriting historical decisions as current guidance.

Changes stay on existing interfaces and were reproduced by failing tests first:

- Native parse-only `--validate-config` loads no Package. `run --check` is the
  separate initialize/seal/shutdown operation.
- CMake fills in the installed `aster_runtime --config` systemd command, which
  is exercised in an integration test; no actual systemd manager was run.
- A dynamic factory returning the wrong type is rejected and destroyed without
  adding an instance.
- Old graph/resolve/build commands warn about migration; there is no second
  Runtime YAML parser or new graph abstraction.

After these updates, the macOS host passed 37 C++ tests each with AppleClang,
LLVM 18, ASan/UBSan and TSan. All 130 Python tests passed, including the separate
installed SDK consumer. Source-wide clang-format 18, targeted clang-tidy 18,
Ruff, forbidden dependency/pin checks, spelling and bilingual Doxygen/Sphinx
builds passed. Linux `vcan`, systemd, Zephyr and physical boards remain unverified.

Existing uncommitted changes are preserved. Legacy repositories and robot
business code are untouched. No commit, tag, release or remote mutation is made.
